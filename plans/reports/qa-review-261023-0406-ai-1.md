**Kiểm chứng:**
- `supported` JSON mode bảo đảm JSON hợp lệ nhưng không bảo đảm schema; Structured Outputs bảo đảm schema.
  > While both ensure valid JSON is produced, only Structured Outputs ensure schema adherence.  
  > — https://developers.openai.com/api/docs/guides/structured-outputs
  _OpenAI-specific._
- `supported` Ràng buộc: mọi field required (optional giả lập bằng union với null), additionalProperties: false, giới hạn kích thước/độ sâu.
  > Although all fields must be required (and the model will return a value for each parameter), it is possible to emulate an optional parameter by using a union type with null.  
  > — https://developers.openai.com/api/docs/guides/structured-outputs
  _Cùng trang: 'up to 5000 object properties total, with up to 10 levels of nesting'._
- `outdated` Request đầu tiên với một schema mới có thêm độ trễ.
  > Note: for fine tuned models, the first request you make with any schema will have additional latency as our API processes the schema, but subsequent requests with the same schema will not have additional latency. Other models do not have this limitation.  
  > — https://developers.openai.com/api/docs/guides/structured-outputs
  _Trước đây áp dụng mọi model; docs hiện tại giới hạn cho fine-tuned model (một ví dụ khác trên trang vẫn ghi chung chung — docs không nhất quán)._
- `supported` Refusal vì an toàn có trường refusal riêng, phát hiện được bằng code.
  > Explicit refusals: Safety-based model refusals are now programmatically detectable  
  > — https://developers.openai.com/api/docs/guides/structured-outputs
- `supported` Chạm giới hạn token thì response incomplete, phải kiểm trước khi parse.
  > This can happen in the case of a refusal, if the model refuses to answer for safety reasons, or if for example you reach a max tokens limit and the response is incomplete.  
  > — https://developers.openai.com/api/docs/guides/structured-outputs
- `supported` Đúng schema không có nghĩa đúng nội dung; sửa bằng chỉ dẫn, ví dụ, tách tác vụ.
  > Structured Outputs can still contain mistakes. If you see mistakes, try adjusting your instructions, providing examples in the system instructions, or splitting tasks into simpler subtasks.  
  > — https://developers.openai.com/api/docs/guides/structured-outputs
- `supported` Function calling với strict cho bảo đảm tương tự với arguments.
  > Setting strict to true will ensure function calls reliably adhere to the function schema, instead of being best effort.  
  > — https://developers.openai.com/api/docs/guides/function-calling

**Độ khó:** hard thật · hợp level middle, senior — Xử lý failure mode thật của structured output; nhưng nặng chi tiết API.
**Dùng trong phỏng vấn:** ~6 phút, 5 ý hỏi, chấm được — Điểm chấm rõ nhưng quá nhiều ý và gắn một vendor.

**Hướng dẫn cho người duyệt junior**
- Câu này kiểm tra: Biết các mức bảo đảm khi bắt LLM trả JSON và cách xử lý các ca lỗi.
- Ý bắt buộc: Chỉ dặn trong prompt: không bảo đảm; JSON mode: cú pháp hợp lệ; structured/strict: đúng schema; Kiểm finish reason/trạng thái incomplete trước khi parse; không tự vá JSON bị cắt; Refusal là nhánh riêng, kiểm trước khi parse; Đúng schema chưa chắc đúng nội dung: validate ngữ nghĩa bằng code; Retry theo loại lỗi, không retry y nguyên
- Dấu hiệu trả lời sai: Nghĩ JSON mode bảo đảm đúng schema; Parse JSON mà không kiểm output bị cắt; Tin giá trị trong JSON hợp lệ là đúng
- Câu hỏi nối tiếp: Điểm chấm trả về đúng schema nhưng nằm ngoài thang 0–10: bạn xử lý ở đâu và báo lỗi cho model thế nào?
