## High
**H1. `--runs N` runs each pass in a new event loop while the LLM gateway client is a process-global bound to the first loop** — `evals/simulate.py:135`.
`by_run = [asyncio.run(run_all(...)) for i in ...]` creates N event loops. `app/llm/gateway.py:183-188` caches `_gateway` (with one `AsyncOpenAI`/httpx pool, `gateway.py:49-51`) for the process; `LlmSimulator` and `LlmEvaluator` (`agents/evaluator_provider.py:44-52`) hold it. Keep-alive connections opened in run 1 belong to a closed loop; run 2 typically fails with `RuntimeError: Event loop is closed` / anyio errors (or the gateway's retry/fallback masks it as degraded output). The RAG pool already guards against this (`repository.py:140-142`, `rag_pool_replaced reason=event_loop_changed`), the gateway does not. Mock test `test_runs_two_sessions_same_persona_in_process_and_skewed_requirements` cannot catch it (no network client). This is the tool step 7 (baseline `--runs 4`) depends on, and it can only be found once the key is back.
Fix (simplest, one loop for all runs):
```python
async def run_many(ids, simulator, args, runs):
    return [await run_all(ids, simulator, args.base_url, args.duration, args.concurrency, args.serve,
                          run=i if runs > 1 else None) for i in range(1, runs + 1)]
by_run = asyncio.run(run_many(ids, simulator, args, runs))
```
`run_all` is already async, so no other change. Optionally add a test that runs 2 runs through a fake gateway holding an `httpx.AsyncClient(transport=MockTransport)` to lock it in.

## Medium
**M1. Pooled stdev mixes adversarial and skewed personas into the noise estimate** — `evals/sim_runs.py:18-26,59-62`.
`scores_by_persona` takes every persona. `end_early`/`one_word_answers`/`injection_attempt` have very different score dynamics (often near-floor, low variance) and inflate df with near-zero SS, biasing `s_p` down, i.e. making 1.2x comparisons in phase 04 look tighter than they are. Fix: pass `personas` and filter `not p.behaviors and p.quality in QUALITIES` (same rule as `strong_weak_gap`), or report `pooled_stdev` for core matrix and `pooled_stdev_all` separately. Update doc 09 accordingly.

**M2. Probe question 4 and 1 "ok" criteria do not answer the question** — `scripts/probe_tool_strict_json.py:84-86, 62-64`.
Q4 `ok = s1 == 200 or s4 == 200` is OK whenever either call works; it does not detect "require_parameters changes routing" (L3). Q1 says "content null" but `ok` ignores it. Fix: Q4 `ok=None` (manual, details already printed) or `ok = (s1 == 200) == (s4 == 200) and r1.get("provider") == r4.get("provider")`; Q1 add `and message(r1).get("content") in (None, "")`.
